Python ou TypeScript pour les scripts de chiffrage ?

Ce qui s'est passé en Python

9 scripts de 225 à 479 lignes, tous déterministes et exécutables (code 0). 3 tracebacks pendant le travail, corrigés par les agents. 38 défauts de typage latents (cellule vide → None, variable non définie dans une branche) que pyright voit et que Python laisse passer jusqu'au prochain dossier.

2 ModuleNotFoundError par run (9/9) : import à tâtons d'une bibliothèque absente.

Ce que TypeScript aurait changé

Pour : strict + noUncheckedIndexedAccess auraient refusé à la compilation la plupart des 38 défauts, avant toute exécution. Le résultat serait le même JSON, mais des scripts qui survivent au dossier suivant.

Contre : la chaîne existante est Python (openpyxl, ReportLab pour le PDF DR, uv, plan-tools de Jo, recalcul LibreOffice). Lire un .xlsx en TS (exceljs) est plus verbeux, et ReportLab n'a pas d'équivalent fidèle en JS pour le gabarit DR. Deux langages dans un même dossier, c'est deux chaînes d'outils à onboarder pour chaque estimateur.

Recommandation. Rester en Python pour le chiffrage et la soumission, mais prendre à TypeScript ce qui compte : le typage strict avant exécution. Concrètement : pyright --strict via agent-lsp dans le profil estimation, annotations de type dans chiffrage.py, et un gabarit de script fourni dans le kit. TS/TSX reste le bon choix pour les canvas et tableaux de bord comme celui-ci, pas pour la chaîne d'estimation.
